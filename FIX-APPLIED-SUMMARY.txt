WHAT THE PROBLEM WAS
═══════════════════════════════════════════════════════════════════

You said: "A lot of numbers. I don't know what alphabets they are writing"

Those "numbers and letters" were:
1. ANSI escape sequences (terminal control codes)
2. RGB color values (those "numbers" you mentioned)
3. Example: ^[[<35;122;40M = ESC + Red:35 Green:122 Blue:40

**Why they appeared:**
- COLORTERM=truecolor environment variable was set
- This forces npm, git, Next.js to emit 24-bit color codes
- These codes BYPASS normal color controls
- During npm install hangs, millions of codes flooded terminal
- Terminal showed them as raw garbage text
- You had to force-quit the terminal

TECHNICAL DETAILS (FOR REFERENCE)
═══════════════════════════════════════════════════════════════════

The garbled numbers/letters you saw:
- ^[[ = ESC character (keyboard "Escape" key, ASCII code 27)
- 35;122;40 = RGB color values (red=35, green=122, blue=40)
- M = end of color formatting command

Tools like Next.js 16 emit:
  \e[38;2;35;122;40m  (set text color to RGB 35,122,40)
  \e[48;2;255;0;0m    (set background to red)

When terminal processing gets corrupted, you see these as-is:
  ^[[<35;122;40M instead of actual colors

COLORTERM=truecolor tells tools "use 24-bit colors"
But this OVERRIDES FORCE_COLOR=0 protection!

✓ SOLUTION: Unset COLORTERM entirely
